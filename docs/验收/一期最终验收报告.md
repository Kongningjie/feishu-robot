## 3. 安全检查

- 源码和 Git 变更未发现真实 App Secret、访问令牌或完整身份标识；
- `.env` 被 Git 与 Docker 构建上下文排除；
- 镜像内不存在 `/app/.env` 与测试目录，应用以 UID 100 非 root 用户运行；
- API 不返回完整 `open_id`、邮箱、`message_id`、飞书错误明细或消息正文；
- 页面使用 DOM `textContent` 构建业务数据，不使用 `innerHTML`；
- CSRF、CSP、Host 白名单、请求限流和安全响应头已启用；
- 本地网关仅绑定 `127.0.0.1`，应用和 Redis 不直接暴露宿主机端口。

## 4. 性能与可靠性

- 模板解析接受300行业务数据并拒绝第301行；
- 发送编排处理300名接收人且保持配置并发上限；
- Redis Lua 原子抢占、唯一锁持有者、逐人即时落库和7天结果 TTL 已实现；
- 中断任务保存在活跃集合中，实例按配置周期恢复；飞书调用使用稳定幂等键，已成功人员不会再次进入发送队列。

## 5. 已知限制

1. 真实飞书交互式卡片样式、按钮和消息体上限仍需真实 API 校准；
2. 公司网关、日志平台和告警平台只能提供厂商无关配置与样例，实际接入和触发验证待公司环境完成；
3. FastAPI TestClient 依赖链存在一条 Starlette/httpx 弃用提示，不影响当前功能；
4. 一期仍不支持定时任务、多阶段、多维表格、群组、外部联系人、预览编辑、选择性发送或历史管理后台。

## 6. 下一步真实联调门槛

- 使用已轮换且安全注入的 App ID/App Secret；
- 提供公司域名下的脱敏测试表直链及阶段名称；

- 先执行只读预览，再核对接收人和内容，最后单独确认真实发送；
- 联调结束后清理测试结果并把飞书错误码映射和消息大小上限回填文档。
