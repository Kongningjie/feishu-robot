# 阶段2：确认发送与可靠性闭环

> 状态：待实施  
> 前置阶段：阶段1已验收  
> 依据：[飞书机器人跟催-冻结实施方案](飞书机器人跟催-冻结实施方案.md)  
> 阶段边界：本阶段实现发送、幂等和失败重试；不完成最终前端和生产部署。

## 1. 阶段目标

基于阶段1生成的不可变预览快照，完成机器人消息卡片生成、人工确认发送、逐人状态记录、幂等控制、失败隔离、有限自动重试和人工仅重试失败项，形成可靠的发送闭环。

## 2. 前置检查

开始本阶段前必须确认：

- 阶段1验收通过且工作日志完整；
- 预览快照结构和Redis键已稳定；
- 飞书机器人能力已发布；
- 应用身份具备消息发送权限；
- 测试接收人在应用可用范围内；
- App Secret已经轮换并通过安全方式注入。

## 3. 实施范围

### 3.1 消息卡片

- 实现固定催办卡片模板；
- 展示项目名称、阶段、截止时间状态和未填业务领域；
- 提供“打开电子表格”按钮；
- 同一申请人的业务领域按表格顺序展示并去重；
- 发送前校验序列化消息体大小，禁止静默截断；
- 不在卡片中提供“已完成”按钮。

### 3.2 确认发送

- 实现 `POST /api/v1/previews/{previewId}/send`；
- 只允许对24小时内的 `READY`快照执行发送；
- 发送时严格使用预览快照，不重新读取或比对表格；
- 接口快速返回 `202 Accepted`，发送过程异步执行；
- `SENDING`或已完成状态下重复调用时返回当前结果，不重复创建任务。

### 3.3 状态机与幂等

- 实现 `READY → SENDING → SUCCESS/PARTIAL_SUCCESS/FAILED`；
- 使用Redis Lua脚本或等价事务原子迁移状态；
- 增加发送/重试分布式锁，锁值必须包含唯一持有者标识；
- 按申请人保存发送状态，成功一人立即落库；
- 页面刷新、网络重试、多实例并发和重复点击均不得造成成功用户重复发送；
- 发送结果保留7天。

### 3.4 失败隔离和重试

- 每个申请人作为独立发送单元；
- 默认并发数5，并支持配置；
- 网络超时、HTTP 429和飞书5xx最多自动重试2次；
- 使用带抖动的指数退避，优先遵循 `Retry-After`；
- 权限不足、用户无效、卡片非法等不可恢复错误不重试；
- 单人失败不影响其他接收人；
- 实现 `POST /api/v1/previews/{previewId}/retry-failures`；
- 人工重试不接收客户端人员列表，只从服务端结果提取失败项；
- 成功项、异常项和过期快照禁止进入重试队列。

### 3.5 结果查询

- 扩展 `GET /api/v1/previews/{previewId}`返回发送进度；
- 返回总状态、成功数、失败数、尝试次数和脱敏错误信息；
- 前端API响应不暴露完整 `open_id`、邮箱、消息正文或飞书内部敏感信息；
- 记录飞书返回的 `message_id`，日志和响应按要求脱敏。

## 4. 测试范围

- 卡片内容、顺序、按钮链接和大小限制测试；
- 状态机合法和非法迁移测试；
- Redis原子抢占和分布式锁测试；
- 双击发送、并发发送和请求重放测试；
- 逐人成功、部分失败和全部失败测试；
- 429、超时和5xx重试测试；
- 不可恢复错误不重试测试；
- 人工仅重试失败项测试；
- 快照过期后禁止发送或重试测试；
- 应用重启后成功项不重复发送测试；
- 脱敏日志和API响应测试。

## 5. 阶段交付物

- 消息卡片构建器；
- 消息发送客户端实现；
- 发送编排服务；
- Redis状态机、结果仓储和分布式锁；
- 确认发送、结果查询和失败重试API；
- 对应单元测试和集成测试；
- 阶段工作日志。

## 6. 完成标准

满足以下条件才能结束阶段2：

1. 一份有效预览可以确认后向每名接收人发送一张卡片；
2. 同一 `previewId`重复请求不会造成重复消息；
3. 单人失败不会影响其他人；
4. 可恢复错误最多自动重试2次；
5. 人工重试只处理当前失败项；
6. 已成功人员在进程重启或多实例并发下仍不重复发送；
7. 结果可以查询7天，且敏感字段已脱敏；
8. 所有新增测试通过，Ruff检查通过。

## 7. 本阶段禁止事项

- 不改变阶段1的模板和预览规则；
- 不实现定时扫描或自动发送；
- 不允许前端勾选或修改接收人；
- 不发送到群组、部门或外部联系人；
- 不进行生产发布；
- 不提前实施阶段3内容。
