# 阶段1：数据接入与预览闭环

> 状态：已实施（Mock 集成测试验收；真实联调按约定后置）  
> 前置阶段：无  
> 依据：[飞书机器人跟催-冻结实施方案](飞书机器人跟催-冻结实施方案.md)  
> 阶段边界：本阶段只实现“读取、解析、匹配、聚合、预览”，禁止发送任何消息。

## 1. 阶段目标

完成从用户输入飞书表格链接和硬件阶段，到生成不可变预览快照的完整后端链路。系统能够准确识别指定阶段的未填记录，通过申请人邮箱换取 `open_id`，按责任人聚合待填业务领域，并将预览快照保存至 Redis。

## 2. 实施范围

### 2.1 基础设施

- 完善 Python 3.11、FastAPI、Pydantic Settings、httpx 和 Redis 工程配置；
- 建立统一异常、响应模型和结构化日志；
- 初始化共享异步 HTTP 客户端和 Redis 连接；
- 增加配置启动校验，禁止缺少必要配置时进入可用状态；
- 完善 `/health/live` 和 `/health/ready`，就绪检查覆盖 Redis。

### 2.2 飞书数据访问

- 获取、缓存和刷新 `tenant_access_token`；
- 校验允许访问的飞书域名；
- 解析 `/sheets/` 链接中的 `spreadsheet_token` 和 `sheet_id`；
- 将 `/wiki/` 链接解析为底层普通电子表格；
- `/wiki/` 底层存在多个页签时，要求改用包含 `sheet_id` 的直链；
- 获取电子表格文件名和工作表信息；
- 读取目标工作表有效数据范围；
- 对飞书超时、限流、权限和资源不存在错误做统一转换。

### 2.3 模板解析

- 唯一定位 `截至时间`、`硬件阶段`、`业务领域`、`申请人`、`申请人邮箱`；
- 对阶段名执行去除首尾空格、不区分大小写的完整匹配；
- 读取目标阶段对应的唯一截止时间；
- 跳过业务领域为空的部门行、分隔行和备注行；
- 将 `null`、空字符串、纯空格和公式空字符串识别为未填；
- 将 `0`、`无需求`、`不适用`等非空值识别为已填；
- 限制最多300个业务数据行。

### 2.4 责任人匹配与聚合

- 读取 `申请人`用于预览展示；
- 读取并规范化 `申请人邮箱`；
- 对邮箱去重后批量调用 `batch_get_id`换取 `open_id`；
- 按 `open_id`聚合业务领域，保持表格原顺序并去重；
- 限制最多300名不同申请人；
- 邮箱缺失、格式非法、外部成员或无法映射时形成行级异常；
- 不允许使用姓名、工号或 `@成员` mention token 猜测身份。

### 2.5 预览快照

- 实现 `POST /api/v1/previews`；
- 服务端生成不可预测的 `previewId`；
- Redis保存不可变预览快照，TTL为24小时；
- 快照保存项目名称、表格链接、阶段、截止时间、`open_id`、显示名、脱敏邮箱、待填业务领域和异常；
- 前端响应不得包含完整邮箱或 `open_id`；
- 实现 `GET /api/v1/previews/{previewId}`读取预览；
- 待催人数为零时正常返回空预览，不进入发送状态。

## 3. 错误处理要求

结构性错误必须阻断预览，包括：

- 非法链接或不支持的 wiki 节点；
- 工作表不存在或应用无读取权限；
- 关键表头缺失或重复；
- 阶段不存在或匹配不唯一；
- 截止时间缺失、非法或不唯一；
- 超过300行或300名接收人。

行级错误只隔离对应记录，正常记录仍进入预览，包括：

- 申请人或申请人邮箱缺失；
- 邮箱格式非法；
- 邮箱不能映射为唯一企业成员；
- 一行出现多个申请人。

## 4. 测试范围

- URL和域名校验单元测试；
- wiki/sheets解析和飞书错误映射测试；
- 关键表头、阶段和截止时间解析测试；
- 所有空值与非空值边界测试；
- 邮箱批量映射、去重和异常隔离测试；
- 责任人聚合顺序测试；
- 300行、300人边界测试；
- Redis快照写入、读取和过期测试；
- 预览API集成测试；
- 日志脱敏测试。

## 5. 阶段交付物

- 可用的飞书异步客户端；
- 可用的模板解析器；
- 可用的责任人匹配与聚合服务；
- Redis预览仓储；
- 创建和查询预览API；
- 对应单元测试、集成测试和配置说明；
- 阶段工作日志。

## 6. 完成标准

满足以下条件才能结束阶段1：

1. 输入合规表格链接和阶段名称后，可以返回正确的预览清单；
2. 只识别指定阶段的空单元格；
3. 邮箱能够批量换取 `open_id`，同一人只出现一次；
4. 结构错误阻断，行级错误隔离；
5. 快照在Redis保存24小时，响应不泄露完整邮箱和用户ID；
6. 所有新增测试通过，Ruff检查通过；
7. 未调用任何飞书消息发送接口。

## 7. 本阶段禁止事项

- 不实现确认发送；
- 不发送测试消息或催办消息；
- 不实现自动重试和人工重试；
- 不完善最终交互页面；
- 不做Docker生产部署和上线验收；
- 不提前实施阶段2或阶段3内容。
