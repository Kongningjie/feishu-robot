## 实现内容

1. 新增固定消息卡片构建器，包含项目、阶段、按原顺序排列的业务领域、截止时间状态和工作表按钮；发送前按 UTF-8 序列化后的完整请求体执行大小校验，超限返回 `MESSAGE_TOO_LARGE`，不截断。
2. 扩展飞书客户端消息发送能力，使用 `open_id` 单聊发送交互式卡片，记录 `message_id`；对超时、429、5xx、权限、接收人和非法消息进行标准化分类。
3. 新增确认发送和失败项重试接口，均快速返回 `202 Accepted`，且不接收请求体或客户端人员列表。
4. 新增受控并发发送编排，默认并发 5；可恢复错误最多自动重试 2 次，使用带抖动指数退避并优先遵循 `Retry-After`；单人失败不影响其他人。
5. 扩展查询接口，返回总状态、成功数、失败数、待处理数、总尝试次数和逐人脱敏结果；不返回完整 `open_id`、邮箱、`message_id`、卡片正文或飞书错误明细。

## 状态机与幂等决策

- 状态流转：`READY → SENDING → SUCCESS/PARTIAL_SUCCESS/FAILED`，人工重试使用 `PARTIAL_SUCCESS → RETRYING → SUCCESS/PARTIAL_SUCCESS`；
- `reminder:result:{previewId}` 保存总体状态及快照副本，TTL 7 天；`reminder:result:{previewId}:recipients` 按 `open_id` 保存逐人结果，TTL 7 天；
- `reminder:lock:{previewId}` 使用唯一持有者值和短 TTL；Lua 脚本原子完成首次发送/人工重试抢占，逐人写入和最终状态提交均校验锁持有者；
- 成功人员状态即时落 Redis。重复点击、请求重放、多实例竞争或新进程再次调用发送接口时只返回已有结果，不创建新发送任务；
- 预览到期后不能开始发送或人工重试；已产生的结果通过内部保存的快照副本继续查询 7 天；
- 人工重试只从服务端结果筛选 `FAILED` 项，绝不接受客户端选择，`SUCCESS` 项不会再次发送。

## Mock 故障注入场景

- 消息卡片内容、领域顺序、按钮链接、截止状态和体积超限；
- 双击/并发确认发送、重复请求及应用重启后的成功项保护；
- 逐人全成功、部分失败、全部失败及失败隔离；
- HTTP 429 和 `Retry-After`、网络超时、飞书 5xx 的两次自动重试上限；
- 权限/接收人/消息非法等不可恢复错误不重试；
- 人工仅重试失败项、非法状态拒绝和过期快照拒绝；
- 并发数上限；
- `open_id`、完整邮箱、完整 `message_id`、卡片正文和飞书内部错误不进入 API 响应；
- 两个新增写接口的 `202` 状态码及统一响应外壳。
