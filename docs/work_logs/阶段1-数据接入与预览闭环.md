## 关键实现决策

1. 严格采用 `success/code/message/data` 统一响应外壳，包含参数错误、业务错误、404 和健康检查。
2. 阶段 1 只暴露创建与查询预览接口；发送和失败重试路由不开放，飞书客户端不提供消息发送方法。
3. `/sheets/` 直链强制要求唯一 `sheet` 参数；`/wiki/` 仅接受底层普通电子表格，多个页签时阻断并要求直链。
4. `tenant_access_token` 使用 Redis 缓存并在有效期前失效，本地缓存同步记录有效期；令牌失效时仅刷新并重放一次请求。
5. 模板解析采用关键表头全局唯一校验，阶段名去空格后不区分大小写完整匹配；只扫描业务领域非空的数据行。
6. 邮箱是唯一身份来源。邮箱先规范化和去重，再批量映射；聚合以 `open_id` 为键并保持业务领域原顺序去重。
7. Redis 使用 `SET NX EX` 写入快照，确保首次写入后不可覆盖；TTL 默认 86400 秒。
8. 内部快照保留发送阶段所需的 `open_id`，不保存完整邮箱；外部响应仅包含显示名和脱敏邮箱。
9. Windows 环境显式增加 `tzdata` 依赖，确保 `Asia/Shanghai` 时区解析一致。
