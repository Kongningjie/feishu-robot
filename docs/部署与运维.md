# 飞书样机需求跟催服务部署与运维

## 1. 部署边界

服务仅允许部署在公司内网。浏览器必须经公司网关的 HTTPS 和统一鉴权访问，应用容器不得直接映射公网端口。仓库中的 Nginx 仅用于本地双实例验收，不能替代公司网关。

## 2. 环境变量

| 变量 | 必需 | 默认值 | 说明 |
|---|---:|---|---|
| `APP_ENV` | 是 | `local` | 生产使用 `production` |
| `APP_TIMEZONE` | 否 | `Asia/Shanghai` | 业务时区 |
| `LOG_LEVEL` | 否 | `INFO` | 结构化日志级别 |
| `ALLOWED_HOSTS` | 是 | 本地域名 | 网关转发的 Host 白名单，生产必须改为公司域名 |
| `CSRF_ENABLED` | 是 | `true` | 写接口 CSRF 双提交校验 |
| `CSRF_COOKIE_SECURE` | 是 | `false` | HTTPS 环境必须设为 `true` |
| `RATE_LIMIT_ENABLED` | 是 | `true` | Redis 共享接口限流 |
| `RATE_LIMIT_REQUESTS` | 否 | `60` | 窗口内每客户端请求数 |
| `RATE_LIMIT_WINDOW_SECONDS` | 否 | `60` | 限流窗口秒数 |
| `FEISHU_APP_ID` | 是 | 无 | 飞书自建应用 ID |
| `FEISHU_APP_SECRET` | 是 | 无 | 必须由容器 Secret 或公司密钥系统注入 |
| `FEISHU_ALLOWED_HOSTS` | 是 | 示例公司域名 | 可输入的飞书表格域名白名单 |
| `REDIS_URL` | 是 | `redis://localhost:6379/0` | 生产使用带认证和 TLS 的公司 Redis 地址 |
| `PREVIEW_TTL_SECONDS` | 否 | `86400` | 预览有效期 |
| `RESULT_TTL_SECONDS` | 否 | `604800` | 结果保留时间 |
| `SEND_CONCURRENCY` | 否 | `5` | 单任务发送并发数 |
| `SEND_AUTO_RETRIES` | 否 | `2` | 可恢复错误自动重试次数 |
| `SEND_LOCK_TTL_SECONDS` | 否 | `600` | 分布式锁 TTL |
| `RECOVERY_SCAN_SECONDS` | 否 | `30` | 中断任务恢复扫描间隔 |
| `SEND_TASK_TIMEOUT_SECONDS` | 否 | `600` | 发送任务超时告警阈值 |
| `MESSAGE_MAX_BYTES` | 否 | `30000` | 序列化消息请求体上限 |

`.env` 仅用于本地验收且已被 Git 和 Docker 构建上下文排除。生产环境不要挂载仓库中的 `.env`，应在编排平台配置 Secret 引用。

## 3. 本地双实例验收

```powershell
docker compose build
docker compose up -d
docker compose ps
Invoke-RestMethod http://127.0.0.1:8000/health/live
Invoke-RestMethod http://127.0.0.1:8000/health/ready
```

默认启动两个无状态应用实例、一个共享 Redis 和一个仅绑定 `127.0.0.1` 的验收网关。应用和 Redis 均不直接映射宿主机端口。

停止服务但保留 Redis 数据：

```powershell
docker compose down
```

删除本地验收数据属于破坏性操作，仅在确认无需保留后执行：

```powershell
docker compose down --volumes
```

## 4. 生产发布

1. 从已评审提交构建带不可变版本标签的镜像；
2. 执行镜像漏洞扫描和密钥扫描；
3. 在公司编排平台注入 App ID、App Secret、Redis URL 和 Host 白名单；
4. 每个容器运行一个 Uvicorn 进程，通过副本数横向扩容；
5. 网关启用 HTTPS、统一鉴权、访问日志和外层限流，只转发公司内网流量；
6. 发布后先检查 `/health/live`，再检查 `/health/ready`；
7. 采集 JSON 标准输出日志和 `/internal/metrics`，应用告警规则；
8. 用脱敏表和内部测试账号执行冒烟测试后再开放给 TPM。

就绪检查不会主动调用飞书 API。首次真实读表或发送前必须完成凭据轮换和权限复核。

## 5. 可观测性

- 所有日志为单行 JSON，包含 `timestamp`、`level`、`logger`、`message`、`requestId` 和脱敏 `previewId`；
- HTTP 响应返回 `X-Request-ID`，可用于日志关联；
- `GET /internal/metrics` 使用统一响应外壳，提供请求、预览、发送、飞书限流、令牌刷新失败和 Redis 错误计数；
- [告警规则样例](../deploy/alerts.example.yml) 为厂商无关格式，接入公司平台时需转换成对应规则语法；
- 不采集 TPM 身份、完整邮箱、完整 `open_id`、完整 `message_id`、完整工作表标识或消息正文。

## 6. 回滚

1. 停止向新版本分配流量；
2. 将应用镜像回滚到上一已验收的不可变标签；
3. 不回滚或清空 Redis。预览、逐人成功状态和发送结果必须保留，避免成功人员被重复发送；
4. 检查新旧版本的 Redis 数据结构兼容性；本期阶段1至阶段3保持兼容；
5. 验证存活、就绪和现有结果查询，再逐步恢复流量；
6. 若发送任务中断，恢复扫描会在锁 TTL 到期后只处理未完成项，并使用稳定幂等键调用消息接口。

## 7. 故障排查

| 现象 | 检查 | 处置 |
|---|---|---|
| `CONFIG_NOT_READY` | 响应中的缺失变量名 | 修正 Secret/环境变量后滚动重启 |
| `REDIS_NOT_READY` | Redis 网络、认证、TLS、容量 | 恢复 Redis；写接口限流故障时默认拒绝请求 |
| `CSRF_VALIDATION_FAILED` | 是否通过页面访问、Cookie/Header 是否齐全 | 重新加载页面，不要绕过网关或复用过期页面 |
| `RATE_LIMITED` | 请求频率、重复点击、网关重放 | 等待窗口结束并检查客户端行为 |
| 长时间 `SENDING/RETRYING` | 活跃任务、锁 TTL、恢复日志 | 确认没有旧实例执行后等待恢复扫描，不手工清空成功项 |
| 飞书 429 | `feishu_rate_limited_total` | 降低并发并检查租户限额 |
| 令牌刷新失败 | `token_refresh_failure_total`、Secret 版本 | 校验凭据注入和应用状态，禁止在日志中打印 Secret |
| 卡片过大 | `MESSAGE_TOO_LARGE` | 拆分源表责任范围；系统不会静默截断 |

## 8. 上线前清单

- `ALLOWED_HOSTS` 为实际公司网关域名；
- `CSRF_COOKIE_SECURE=true`；
- App Secret 已轮换且未进入源码、镜像层或日志；
- Redis 使用公司标准认证、加密、备份和访问控制；
- 两个以上实例共享 Redis 的幂等用例通过；
- 真实卡片、按钮链接、3～5 个内部测试账号和飞书错误码已完成联调；
- 公司日志及告警平台已实际接入并触发验证；
- 回滚镜像标签和当值联系人已记录在发布单中。
